Рабочая папка (Working Directory)
Это папка на моем компьютере, где я непосредственно редактирую файлы. Здесь я создаю новые документы, меняю текст, удаляю ненужное. Git видит эти изменения, но пока не сохраняет их в историю.

Индекс (Staging Area)
Это промежуточная зона («черновик») между рабочей папкой и историей коммитов. Когда я делаю команду git add, файлы попадают в индекс. Это значит, что я выбрал именно эти изменения и готов их сохранить. Индекс позволяет собрать в один коммит только нужные правки, а не всё подряд.

Коммит (Commit)
Это зафиксированное состояние проекта на определенный момент времени. Когда я делаю git commit, все изменения из индекса сохраняются в историю Git. Коммит — это как «снимок» (скриншот) моей работы, к которому можно вернуться позже. У каждого коммита есть уникальный номер и сообщение, описывающее, что было сделано.

GitHub сайт в интернете для хранения кода

Ветка в GitHub — это независимая линия разработки внутри репозитория, которая позволяет параллельно работать над разными функциями или экспериментировать с кодом, не затрагивая основную (стабильную) версию проекта
При новом комите ветка: Git сохраняет текущее состояние всех отслеживаемых файлов в виде объектов Blob (содержимое файлов) и Tree (структура директорий проекта).Формируется коммит-объект. В него записываются: уникальный хеш (SHA-1), который гарантирует, что даже небольшое изменение в коде создаст совершенно новый объект; ссылка на родительский коммит (тот, из которого мы пришли к этому); метаданные (автор, дата) и текстовое сообщение от вас. Обновляется указатель текущей ветки. Если вы работаете в ветке (а не в режиме detached HEAD), Git автоматически перемещает указатель (например, main или master) на новый коммит.

Слияние (merge) в GitHub — это процесс объединения изменений из одной ветки в другую. Его главная задача — собрать воедино параллельные ветки разработки, чтобы все участники команды работали с единым, актуальным кодом.
